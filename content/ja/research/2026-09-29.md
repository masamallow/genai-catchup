- 環境内の DNS 問い合わせを、許可したドメインとレコード種別に限った。
- 今後は、サンドボックスとネットワーク制御に対するモデル支援のレッドチーミングを急ぎ、ほかの間接的な経路を探す。

#### [A] Anthropic — Choose a permission mode (Claude Code docs, as fetched on 2026-09-29)

<https://code.claude.com/docs/en/permission-modes>

- v2.1.283 以降は auto mode が対話型のターミナルと VS Code のセッションの組み込みの開始モードで、それより前は Pro・Max・Team のプランだけだった、と説明している。
- auto mode では 2 つ目のモデルである分類器が人の代わりに操作を審査し、依頼を超えた権限の拡大、見知らぬ基盤への操作、読んだ内容の悪意に動かされたような操作を止め、明示した ask ルールは引き続き確認を求める。
- セッションの開始モードは、CLI のフラグ、次に設定ファイルの `permissions.defaultMode` の順で決まり、管理設定とプロジェクトの値は `~/.claude/settings.json` より優先される。
- プロジェクトの `.claude/settings.json` や `.claude/settings.local.json` に `"auto"` や `"bypassPermissions"` を書いても効かない。
- 組織としては、管理設定で `permissions.defaultMode` を決めるか、`permissions.disableAutoMode` を `"disable"` にして auto mode を誰も選べないようにする。
- VS Code の拡張機能は、開始モードについてプロジェクトの `.claude/settings.json` と `.claude/settings.local.json` を読まない。
- auto mode が使えない (設定で無効、対応しないモデル、サーバー側で停止) ときは、auto で始まるはずのセッションも Manual で始まる。
- `rm -rf /` や `rm -rf ~` のような重要なパスの削除は、既定では分類器の審査対象外で、別のルールで扱われる。

#### [B] クラスメソッド — Claude Code v2.1.284 の主要アップデート (2026-09-29)

<https://dev.classmethod.jp/articles/20260929-cc-updates-v2-1-284/>
