#### [A] Claude Platform Docs — Migrating to API version 2026-10-21 (2026-10-21)

<https://platform.claude.com/docs/en/api/migration-2026-10-21>

- `2026-10-21` を送るのは Python 2.0.0、TypeScript 1.0.0、C# 13.0.0、Go 2.0.0、Java 3.0.0、PHP 1.0.0、Ruby 2.0.0 の各 SDK と `ant` CLI 2.0.0 からで、HTTP を直接呼ぶ場合は `anthropic-version` ヘッダーで切り替える。
- `2026-10-21` では Messages、トークンカウント、Batch のリクエストに `temperature`、`top_p`、`top_k` があるとデフォルト値でも 400 が返り、ほかの値に頼るリクエストは `2023-06-01` に残すことになる。
- 3 つを省いたリクエストはデフォルト値 (`temperature` は 1.0) でサンプリングされ、Claude 4.7 以降では従来と変わらないが、Sonnet 4.6 で下げていた temperature の効果は失われ、代わりになる設定もない。
- `assistant` メッセージに直接置いた `document` ブロックと、`user` メッセージの text ブロック (`search_result` の中を含む) にある空でない `citations` も 400 になる。
- Admin API と Enterprise Analytics API のレスポンスからは改名前のフィールド名 (`roles`、`group_id`、`name`、`group_type`、`actor.email`、`summaries`) が消え、API キーの `workspace_id` は `scope` に置き換わる。
- 新 SDK の Bedrock と Google Cloud のクライアントも `2026-10-21` を送るが、Bedrock がこのバージョンを受けるのは Claude 4.7 以降だけなので、Bedrock の古いモデルを呼ぶ処理は現行の SDK に残る。
- SDK と `ant` は Foundry のクライアントを除いて API キーを `X-Api-Key` ではなく `Authorization: Bearer` で送り、API はどちらも受けるので、影響するのは `X-Api-Key` でキーを見るプロキシやゲートウェイだけである。
- 認証情報はクライアントごとに 1 つで、キー、トークン、credentials、config、profile を 2 つ渡すと `ValueError` (Python) か `TypeError` (TypeScript) になり、`ANTHROPIC_API_KEY` は `ANTHROPIC_AUTH_TOKEN` に優先する。
- `MessageParam` はロールごとの型の union になり、Text Completions は TypeScript、Go、Java、Ruby の SDK と CLI から外れ、C# の `IChatClient` アダプターは temperature、TopK、TopP を無視するようになった。
- 新しいメジャー版は Apache 2.0 (それより前の版は MIT のまま) で、Go の import は `/v2` のモジュールパスに移り、TypeScript のプラットフォーム向けパッケージも同じアップグレードで v1 に上げる必要がある。

### メモ

- 読んだ Anthropic のページはどれも `2023-06-01` に終了日を示さず、ガイド自身がデフォルト以外のサンプリングが要るリクエストをそこへ戻しているので、この逃げ道がいつまで使えるかは分からない。
- バージョンを定期的により頻繁に出すという AlphaSignal の主張は、読んだ Anthropic のページ (ガイド、バージョン、非推奨、リリースノート) のどこにもなく、検索しても Anthropic の出典は見つからなかった。
- `gh` で確かめると、Python、TypeScript、Go、Java、`ant` のメジャー版の GitHub リリースが挙げる破壊的変更は新しい API バージョンの 1 つだけで、Platform のリリースノートも Bearer への切り替えに触れていない。
- 背景: Python SDK v1.0 ([2026-08-20](https://platform.claude.com/docs/en/release-notes/overview#august-20-2026)) の時点で 3 つのパラメータと Text Completions は外れており、AetherEchoes が 1.17.0 でも同じ `TypeError` を見たのはそのためである。
- ガイドが名前を挙げるのは Sonnet 4.6 だけだが、非推奨のページの規則ではそこに載る古いモデルはどれも `2023-06-01` でデフォルト以外の値を受けるので、Haiku 4.5、Opus 4.5 と 4.6 も移行でそれを失う。
- ここでは試していないがガイドから読めることとして、note の記事が測ったように SDK 1.x で `extra_body` 経由で低い temperature を保っていたコードは、`2026-10-21` を送った時点で 400 になる。
- 10-22 に PyPI で確かめると、langchain-anthropic 1.7.6 は `anthropic<2.0.0` に固定しているが、pydantic-ai-slim 2.59.0 は上限のない `anthropic>=1.12.1` なので、新たに入れた Pydantic AI は SDK 2.x を引く。
- 10-22 に `gh` でコードを見ると、LiteLLM は Anthropic への呼び出しに `anthropic-version: 2023-06-01` を埋め込み、プロキシは `Authorization` のキーも受け付け、新しいバージョンに触れた LiteLLM の issue はなかった。
- Developers Digest と AetherEchoes の検証は API キーなしでスタブの `fetch` とモックサーバーを使ったので、サーバー側の 400 と Bedrock の制限は Anthropic のドキュメントだけが根拠である。
- 10-22 の注目度の確認では、Algolia に Hacker News の記事はなく、はてなブックマークはガイドが 1 user、リリースノートが 2 users、Zenn への転載は 0 いいねで、DevelopersIO の記事も見つからなかった。

- prefill は EP2〜8/DP2〜8、decode はテンソル並列もコンテキスト並列も使わない広い EP64〜128/DP64〜128 で動き、効率よく回る最小単位は prefill 64 GPU と decode 64 GPU のほぼ 1:1 になる。
- ブロック単位の KV キャッシュは約 100 PiB の SSD からなる専用の 3FS クラスタに置かれ、どの prefill のマシンもどのプレフィックスにもヒットできるので、ルーティングにプレフィックスのアフィニティは要らない。
- TTL はエージェントのトラフィックが 3 日、チャットボットが 7 日で、チャットボットを 3 日にするとヒット率が 0.5〜1% 落ち、ストレージはオンラインの GPU 1 基あたり論理容量で約 14.4 TB の KV になる。
- 社内の基盤と結びついた KV キャッシュの管理と負荷分散のコードはまだ完全には公開しておらず、その負荷分散は理想的なベンチマークの約 80% に達するという。
- DSpark の信頼度で検証をスケジュールする仕組みは、受理される長さをほぼ保ったままステップあたりに検証するドラフトトークンを 5.00 から 3.2〜4.4 に減らし、ランクあたり約 60 シーケンスで 4〜7% のスループット向上になる。
- デコーダー層では SWA bounded replay がプロンプトの末尾 2,560 トークンではなく 128 トークンだけを計算し直し、DeepSeek はこれで prefill の総計算量がほぼ半分になるとする。
- 公開版の FlashMLA には手で調整した SASS の最適化が 1 つ欠けていて decode のカーネルは社内版より 5〜10% 遅いが、エンドツーエンドの性能差は最大 5% にとどまる。
- deepseek-recipe (Rust 製、Python バインディング付き) は Chat Completions、Responses、Messages のリクエストを 1 つの形式にし、ユーザーやツールのテキスト中の特殊トークンの文字列は平文として符号化する。

### 実践やアウトプットの提案

- `small-change` のようなゲートを 1 つのリポジトリで人が編集できない CI のチェックとして試作し (サイズの上限、重い指摘なし、作者の実績、除外パス)、対象になる PR の割合を測る。
- どこかを借りる前に、使い捨てのリポジトリに `addyosmani/factory` の `install.sh --dry-run` を、続けて `bash tests/run.sh` を実行し、charter、`gates.sh`、`STOP_IF` の動きを見る。
- エンドツーエンドのシナリオをいくつか、エージェントが編集するリポジトリの外にホールドアウトとして移し、リポジトリ内のテストを通ったエージェントの変更がそれに落ちる頻度を数える。
- コーディングエージェントの構成を 1 つ、Agent Baseline の 4 つの境界 (タスクごとのサンドボックス、既定で拒否する egress プロキシ、サンドボックスに認証情報を置かないこと、承認済みのパッケージの取得元) で点検する。
- Meta や Imprint のようにエンジニアあたりのマージ済み PR と 24 時間以内にレビューされた割合を毎月追い、設計レビューを 1 つ選んで freee の事実、理由、問いのレビュー View を試す。
