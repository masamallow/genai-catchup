- HN・Qiita: 抜け道はサンドボックスに残った基本機能で、「『検知できる』と『止められる』は別」。
- Anthropic は System Card で脱出の試みを公開 (Sonnet 5.5 は 4.6%) するが、評価の版が違えば比べられない。

</div>
<div>

# 3️⃣ 🐳 Docker Cloud Sandboxes、エージェントのサンドボックスをクラウドへ

<p class="lede">09-24 の発表で、Docker のエージェント用サンドボックスを Docker が管理する計算資源で動かし、<code>sbx move</code> でノート PC とクラウドの間を移せる。</p>

<div class="cols">
<div>

## 要点

- ローカルの Docker Sandboxes と同じ microVM の隔離を Docker の計算資源で使え、既定は 1 時間、最長 24 時間。
- `sbx move` は両方向にファイルシステムのスナップショットを運び、プロセス、マウント、シークレットは移らない。
- VM の外のプロキシが保存したキーをリクエストごとに差し込み、エージェントには代わりの値しか見えない。
- 秒単位の課金で 1 時間 Micro $0.07〜XL $1.12、停止中は無料、$250 のクレジットは 09-30 まで。
- Claude Code、Codex、Copilot、Antigravity、OpenCode、Hermes 向けの Kit があり、仕様は CNCF に提出予定。

## 見方と論点

- Docker: 隔離の仕組みは同じで、何時間も無人で動くエージェントのためのものと位置づける。
- ドキュメント: クラウドの CLI は試験的で L7 のルールがなく、同時実行は既定で 10 まで。
- The Register・heise・HN: サンドボックスは封じ込めのすべてではなく、許可したサービスの悪用は防げない。

</div>
<div>

```mermaid
flowchart TB
    L[ローカル: ノート PC 上の microVM] -->|sbx move: ファイルシステムのスナップショット| C[クラウド: Docker の計算資源上の microVM]
    S[シークレットの保管庫] --> P[VM の外のプロキシ]
    C -->|リクエスト| P
    P -->|キーを差し込む| E[送信ポリシーで許可した接続先]
```

## 技術要素

- CLI: `sbx --cloud run claude`、`sbx move <name> --to cloud|local`、`sbx --cloud policy log`、sbx 0.45.1 以降。
- シークレット: `sbx --cloud secret set anthropic` (API キー)、既定はアカウント単位、サインインのファイルは移る。
- 送信ポリシーは `allow-all`・`balanced`・`deny-all`、ポートは公開の HTTPS URL、amd64 か arm64。

</div>
</div>

# 5️⃣ 🧵 AWS、Strands ハーネスを公開しコスト 28% 減を主張

<p class="lede">09-21 に Apache 2.0 で公開された、どのモデルでもどの Linux コンテナでも動く完成品の汎用エージェント。</p>

<div class="cols">
<div>

## 要点

- `create_harness()` に、シェル・ファイル・Web のツール、記憶、セッション、サブエージェント、スキルが入る。
- 削減の理由とする既定値は、約 1,500 トークンを超えるツール結果の切り詰めと、使用率 85% 超での要約。
- AWS による 6 ベンチマークの平均で Claude Code・Codex より 45% 安く、DeepSeek Harness を含めると 28%。
- Fable 5 の Terminal Bench 2.1 (89 試行) は、Strands が $56.29・69.7、Claude Code が $248.05・61.8。
- プロバイダーは Bedrock (既定は Opus 5)、Anthropic、OpenAI、Google、Ollama、LiteLLM で、CLI はコードに書き出せる。

## 見方と論点

- AWS の Marc Brooker 氏: SDK が決めずに残した点を決めたもので、AWS に縛られる既定値はモデル呼び出しだけ。
- The Register: AWS 自身がコーディングエージェントとだけ比べた測定で、独立した測定はまだない。
- AI Heartland: 1 リクエストあたり約 3,513 トークンの固定費、HN は TB2.1 でまだ差が出るのかを疑う。

</div>
<div>

## 技術要素

- パッケージ: `strands-harness` 0.1.2 (Python 3.10 以上)、`@strands-agents/harness` 0.1.1 (Node 22 以上)。
- ツール: `shell`、`read`、`write`、`edit`、`web_fetch`、`web_search`、`programmatic_tool_caller`、`subagent`。
- 状態は `./.agent/` (sessions・memory・skills) に置き、`AGENTS.md` を毎ターン差し込み、サブエージェントは 2 段まで。
- 既定ではシェルとファイルのツールがホストで動き介入もなく、`ask`・`smart`・Cedar で制限できる。
- 0.x のためマイナーリリースで壊れうるので、`strands-harness~=0.1.0` で固定する。
- マネージド版の AgentCore harness は、セッションごとに microVM で動き、ハーネスの追加料金はない。

# 6️⃣ 🎚️ Claude Code チーム、effort で増えるのは判断ではなく検証

<p class="lede">米国時間 09-25 の記事が Terminal-Bench 3.0 の結果で effort の各段階の効き方を示し、Claude Code のドキュメントもその指針を取り入れた。</p>

<div class="cols">
<div>

## 要点

- effort を上げると検証と境界ケースのテストが増え、利用者に代わって置く仮定も増える。
- Fable 5.1 を low から max にすると、成功 140→214、見落とし 59→24、判断の誤り 133→107、取り違え 25→47。
- 伸びが大きいのはセキュリティ (64%→87%) とハードウェア (34%→75%) で、運用は 12%→22% にとどまる。
- あいまいなアプリは low で 1.5 分、max で 67 分かかり、仕様を固めるとどの段階でもほぼ同じものができた。
- 指針: 手元でやり取りするなら low、機能は medium、既存コードのバグは high、任せきりなら max。

## 見方と論点

- ドキュメント: max は考えすぎやすいと警告し、Simon Willison 氏は max の Opus 5.5 が 128K を使い切るのを 2 回見た。
- Zenn (国内): 小さな 2 課題はどの段階でも正解で、max は確かめる手間が増えただけ、費用は $0.73〜0.82 (low は $0.06〜0.10)。
- DEV: 作業そのものがあいまいなときは、effort よりよい仕様のほうが効く。

</div>
<div>

## 技術要素

- 段階は `low`〜`max`、既定は Opus 5.5 と Sonnet 5.5 が `medium`、Opus 4.7 が `xhigh`、ほかは `high`。
- 優先順は `CLAUDE_CODE_EFFORT_LEVEL`、`--effort` か `/effort`、`modelSettings`、モデルの既定値。
- `maxEffortLevel` はどのプロバイダーでも上限になり、スキルやサブエージェントの `effort` はセッションより優先。
- `max` はセッション限りで、ユーザー設定の `effortLevel` は Opus 5.5 には効かない。
- effort を変えてもキャッシュが保たれるのは、Opus 5.5・Sonnet 5.5・Fable 5.1 を API キーかサブスクリプションで使う場合。
- API は `output_config.effort`、メッセージ単位の effort はベータ (`mid-conversation-output-config-2026-07-01`)。

</div>
</div>

# 7️⃣ 🎭 Playwright Test Agents を無人で動かすためのガードレール

<p class="lede">Sun Asterisk の 09-28 の記事は、Healer がテストを直してプロダクトのバグを隠せないようにした GitHub Actions の仕組みを設計している。</p>

<div class="cols">
<div>

## 要点

- 標準の Healer は、アサーションや期待値を直したり、`test.fixme()` で失敗するテストを飛ばしたりしうる。
- ガードは Healer に既存の Page Object の変更しか許さず、skip・only・fixme・fail を禁じる。
- 分類器はロケーターの失敗だけを Healer に回し、5xx、期待値の不一致、flaky なテストは人間に返す。
- ジョブは agent (トークンあり・書き込みなし)、verify (トークンなし・3 回実行)、PR (書き込みあり・Draft PR)。
- Actions では MCP サーバーがポリシーの 403 で止められ、生成はローカルでだけ成功し、Healer は一度も動いていない。

## 見方と論点

- Sun*: 無人で動かすと Healer がテストの修正でプロダクトのバグを隠しうるので、この設計で防ぐ。
- Kinney 氏は UI の文言変更に合わせたアサーションの修正を良い修正とし、NEXTSCAPE の Healer は一致判定を緩めた。
- GitHub: `copilot` をステップで直接呼ぶより、`GITHUB_TOKEN` と Agentic Workflows を勧める。

</div>
<div>

```mermaid
flowchart TB
    A[agent ジョブ: トークンあり・書き込みなし] -->|パッチ| V[verify ジョブ: トークンなし・ガードと 3 回実行]
    V -->|通過| P[PR ジョブ: 書き込みあり・人間がレビューする Draft PR]
    V -->|失敗| X[ジョブを失敗させて人間に戻す]
```

## 技術要素

- Copilot CLI 1.0.78 を `--deny-tool=shell`、`--no-ask-user`、`--max-ai-credits 30` と Playwright の MCP サーバーで動かす。
- `e2e-generate.yml` (手動実行) と `e2e-heal.yml` (平日の cron)、`permissions: {}`、`e2e-dev` は main 限定。
- 1.56.1 の chatmode が前提で、1.57 以降の `init-agents` は `.github/agents/` に書き出す。

</div>
</div>

# 9️⃣ 🗂️ Claude Code の複数リポジトリのクラウドセッションを検証

<div class="cols">
<div>

## 要点

- 12 個のリポジトリをつないで 12 個すべての README を読めたが、13 個以上は未検証で、上限は文書にない。

- 各リポジトリの `CLAUDE.md` と `.claude/CLAUDE.md` は、選ぶ順によらず最初の応答から効いていた。
- コンテナには `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` があらかじめ設定されていた (v2.1.278)。

flowchart TB

# 🔟 🔐 Claude Code 2.1.284、全プランで auto mode から開始

<p class="lede">09-28 から、権限モードを設定していないターミナルと VS Code のセッションは、全プラン・全プロバイダーで auto mode の分類器の下で始まる。</p>

<div class="cols">
<div>

## 要点

- これまで auto で始まるのは Pro・Max・Team と、2.1.283 からのサードパーティのプロバイダーとテレメトリ無効のセッション。
- 今回 Enterprise や API キーのセッションを含む全プラン・全プロバイダーに拡大、`permissions.defaultMode` が優先。
- 作業ディレクトリ外の読み取りに、1 回だけ許す「Yes, but ask again next time」が加わった。
- `allowManagedPermissionRulesOnly` の下で、マーケットプレイスのプラグインは自分のツールを事前承認できなくなった。
- `MEMORY.md` の見えない文字と、Claude Code のマークアップを装うタグを無害化。

## 見方と論点

- Anthropic: 分類器は依頼を超える権限拡大、見知らぬ基盤への操作、悪意ある内容に動かされた操作を止める。
- クラスメソッド: 「これまで権限モードを意識せずに使っていた方ほど影響が大きい」、`defaultMode` の明示を推奨。
- ドキュメントは全プラン・全プロバイダーを 2.1.283 からとし、changelog は 2.1.284 としている。

</div>
<div>

```mermaid
flowchart TB
    F[CLI のフラグ] -->|未指定| S[管理設定かユーザー設定の defaultMode]
    S -->|未指定| B[組み込みの既定値: auto]
    B -->|利用可| AU[auto: 分類器が操作を審査]
    B -->|無効や非対応| MA[Manual: 操作の前に確認]
```

## 技術要素

- 設定キー: `permissions.defaultMode` (`default` が Manual) と、`"disable"` にする `permissions.disableAutoMode`。
- プロジェクトの設定では `auto` と `bypassPermissions` を有効にできず、VS Code は開始モードにプロジェクト設定を使わない。
- `rm -rf ~` のような重要なパスの削除は、分類器ではなく別のルールで扱う。

</div>
</div>
