#### [A] Microsoft — MXC SDK v1.0.0 release notes and the repository's release history (2026-10-07)

<https://github.com/microsoft/mxc/releases/tag/v1.0.0> / <https://github.com/microsoft/mxc/releases>

- v1.0.0, published on 2026-10-07 at 05:54 UTC, is the first stable release of the SDK for Rust, .NET and Node.js and the first GitHub release of the project not flagged as a pre-release.
    - The earlier releases are v0.6.1 (2026-06-02), v0.7.0-rc1 (2026-06-13, titled MXC SDK v0.7.0), v0.8.0 (2026-08-22) and v0.9.0 (2026-09-29), all flagged as pre-releases, and the v0.9.0 notes never call it a release candidate.
- The public API now lives only in versioned entry points, `mxc_sdk::v1`, `Microsoft.Mxc.Sdk.V1` and `@microsoft/mxc-sdk/v1`, which share one operation model and one set of policy concepts across the three languages.
- V1 is the compatibility boundary for the 1.x line, and future changes follow semver 2.0.
- Three execution models: run to completion with captured stdout, stderr, warnings, metadata and a typed outcome; spawn with separate stdin, stdout and stderr pipes on an SDK-owned process handle; spawn with a PTY that takes initial dimensions and resizes at run time, only where the backend can provide terminal semantics.
- The lifecycle API provisions a container and returns an opaque `ContainerId`, then starts, stops and deprovisions it, and runs, spawns or opens a PTY process inside it when the backend supports that.
- Typed APIs also cover backend discovery with capabilities, filesystem policy built from discovered host tools, the user profile and the temporary directory, and telemetry consent, which stays Windows-only, opt-in and subject to administrative restrictions.
- Migration: import from the V1 entry point, replace the legacy sandbox request and lifecycle types with `ContainerRequest`, `ProvisionRequest`, `ExecutionRequest` and `ContainerId`, and rebuild against the 1.0 packages.
- The changelog also retires the pre-v0.9 schema contracts (#1382), makes exact versioned JSON the only FFI configuration input and removes the binding request FFI exports (#1349 to #1352), and merges the Rust SDK crates into one publishable package (#1390).
- Security-related entries include documented and pinned default-deny ingress (#1363), policy rejections reported as exit code 1 with a `policy_validation` code (#1364), IsolationSession refusing `process.env` without `inheritDefaultEnv` (#1339) and dependency bumps for published CVEs (#1124).
- Signed binaries ship as `mxc-release-binaries.zip`, which the notes describe as useful for testing.

#### [A] Microsoft — microsoft/mxc README, schema guide, backend guides and V1 SDK reference (as fetched on 2026-10-10)

<https://github.com/microsoft/mxc>

- The repository, created on 2026-02-06 under the MIT licence, had 2.4k stars and 120 forks when fetched, and describes MXC as an SDK dependency built into the calling application, which chooses the container type, the containment rules and the command.
- Default backends are `processcontainer` on Windows 11 x64 and ARM64, `bubblewrap` on Linux x64 and ARM64 and `seatbelt` on macOS, with `wslc` and `isolation_session` as further Windows backends and `lxc` on Linux.
    - `windows_sandbox`, `microvm` (Nanvix) and `hyperlight` are experimental; the README marks them only in the Windows row, but the Nanvix and Hyperlight guides require `--experimental` on Linux too.
    - Seatbelt needs macOS 15 or later and applies a generated profile through `sandbox_init()`, an API deprecated in headers since macOS 10.8 that still ships; Bubblewrap needs bwrap 0.5.0 or later, and LXC needs root unless the policy asks for no network.
- `processcontainer` resolves at run time to BaseContainer, the newer OS sandbox API, or to the legacy AppContainer path, depending on host support.
    - Process isolation needs Windows 11 24H2 build 26100.9278 or 25H2 build 26200.9278 (the August 2026 update KB5120998), and session isolation builds 26100.9550 or 26200.9550 (the September update KB5124010); 26H1 needs 28000.2804 and 28000.3086.
    - When neither BaseContainer nor the OS filesystem broker is available, `fallback.allowDaclMutation`, `true` by default, lets MXC write ACEs into host DACLs and restore them on exit.
- V1 typed creation accepts `process` (resolved per OS), `processcontainer`, `bubblewrap`, `seatbelt`, `lxc`, `wslc` and `isolation_session`, while the lifecycle operations accept only `isolation_session` and `wslc`.
    - Bubblewrap and Seatbelt run create-and-run only, and discovery may report backends that have no V1 creation API.
    - The README's Node example calls `spawn()` from `@microsoft/mxc-sdk/v1` with a `command`, `network: { egress: { default: 'deny' } }` and `timeoutMs: 30_000`.
- The policy has read-only, read-write and denied path lists plus directional `network.egress` and `network.ingress` (with `hostLoopback`) and `runtimeConfig.networkProxy`, all deny by default.
    - A direct egress rule names numeric CIDRs and ports, e.g. `{"to": [{"cidr": "140.82.112.0/20"}], "ports": [{"protocol": "tcp", "port": 443}]}`, and the legacy host lists of earlier schemas are rejected.
    - On the LXC, Bubblewrap and WSLC backends, one object reached through several paths takes the most restrictive grant, deny over read-only over read-write.
- The `ui` section (`disable` true, `clipboard` "none" and `injection` false by default) is enforced only by ProcessContainer, through the Win32k system-call mitigation and job-object UI limits, and by Seatbelt; IsolationSession and WSLc reject a supplied `ui`, and the other backends apply none.
- Network granularity differs by backend: ProcessContainer filters egress per container with WFP by IP range, protocol and port on the BaseContainer path; Bubblewrap filters IPs and CIDRs inside the sandbox's own namespace and leaves IPv6 destinations unreachable; Seatbelt allows only all-or-nothing outbound plus loopback ports and rejects hostname, IP, CIDR, port and protocol rules.
    - No backend takes hostname rules: hostname policy belongs in a caller-managed proxy, through which proxy-only egress is enforced, while actually using the proxy is cooperative on Seatbelt and Bubblewrap.
- Backends reject policies they cannot enforce before launch instead of silently weakening them, and the README warns that `--audit` "turns off all sandbox security for the workload being analyzed".
- Bubblewrap isolates with namespaces only: the June 2026 Linux roadmap lists seccomp support as not done and notes that the full syscall surface, `io_uring_setup`, `keyctl`, `bpf` and `userfaultfd` included, stays exposed.
- The JSON contract version is kept apart from the product version and from host capability, which is probed at run time; `0.9.0-alpha` is the minimum supported contract, `1.0.0` the stable one and `1.1.0-alpha` the development one.
    - The v1 line drops the aliases `appcontainer`, `appContainer` and `macos_sandbox`, and a future breaking schema line would add a side-by-side V2 namespace instead of replacing V1.
- Windows ProcessContainer offers Learning Mode denial capture, which keeps enforcing and records blocked accesses, and `permissiveLearningMode`, which allows and records them; telemetry stays off unless the run, the Windows user, administrative policy and the application all opt in, and is a no-op off Windows.

#### [A] GitHub Docs — About cloud and local sandboxes for GitHub Copilot (as fetched on 2026-10-10)

<https://docs.github.com/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes>

- Local sandboxing is off by default, so until it is enabled Copilot's shell commands run with the user's full access.
- GitHub states: "Local sandboxing currently sits at the lighter-weight end of this spectrum: it restricts what a process can read, write, and reach on the network, but it does not run your commands inside a separate virtual machine or container."
- Requirements: Seatbelt on macOS 15 or later, bubblewrap 0.5.0 or later on Linux plus util-linux 2.35 or later `unshare` and `nsenter` when outbound traffic is allowed, and a recent Windows 11 update; a feature the host cannot support is reported instead of being weakened.
- On Windows, proxying and host rules need Allow local network and rely on programs honoring proxy settings, so they protect less against direct connections than on macOS and Linux; on Linux, bubblewrap cannot control local-network access separately for spawned processes.
    - Managed settings with `sandbox.enabled` and `sandbox.failIfUnavailable` both `true` block model requests and tool execution when sandboxing cannot be enforced.

#### [A] Anthropic — 2026 Usage Policy update (2026-10-08)

<https://www.anthropic.com/news/2026-usage-policy-update>

- This is the yearly refresh: the new text was published on October 8 and takes effect on November 12, 2026.
    - Anthropic says most changes clarify existing rules, adding examples for Claude's longer, more independent work and for misuse it saw in the past year in influence operations, weapons development and surveillance.
- Rules on deception that were spread across the elections, fraud, privacy and disinformation sections move into a new section, Do Not Engage in Deceptive Campaigns or Artificial Activity, which applies to political and commercial deception alike.
    - It covers hiding who is behind a message, amplifying content through fake accounts or posts, and building the tools and infrastructure for influence operations.
- The elections section is narrowed to deceiving voters or disrupting elections (false information about candidates or how to vote, impersonating candidates or election officials, suppressing turnout) and renamed Do Not Undermine Democratic Processes.
- The blanket ban on personalized vote and campaign targeting is removed because it also caught legitimate civic work, such as nonprofits writing voter information in other languages or election officials sending ballot cure notices.
    - Targeting that relies on deception or misuses voters' personal data stays prohibited under the deceptive-campaigns, surveillance and privacy sections.
- After people tried to build guidance and control software for weapons, the weapons section now says that the software and components that make weapons work, and arming drones and other autonomous vehicles, are covered; Anthropic says this matches how it already enforced the old text.
- The surveillance and criminal-justice section is rewritten: tracking people without consent is prohibited in real time or through analysis of previously collected data, Claude cannot decide or recommend whom to investigate, arrest or charge, and building or improving tools designed for surveillance is prohibited.
    - Anthropic says this changes nothing in what it enforces, and the section now names uses that stay permitted: tracking people agreed to (fraud monitoring), content moderation, journalism and legal research.
- The high-risk requirements are described as unchanged: where use can affect health, legal rights, finances, livelihood or access to essential services, a qualified human in the loop must be able to review and change Claude's recommendations, and the affected person must be told AI was used.
    - The section is rewritten to list which kinds of recommendations are covered and which are not, because customers kept asking whether their use case qualified.
- Following the Model Hardware Standard launch, the same section adds requirements for models connected to hardware that takes autonomous physical actions and might cause injury: a qualified operator must be able to observe and stop the equipment, and the equipment must hold a safe state if Claude is disconnected.
- A new prohibition covers sustained and needless abusive or cruel behavior toward the models, meant only for extreme cases of repeated cruelty with no discernible purpose and not for ordinary frustration, pushback, dark creative themes, or model testing and research.
    - It follows Claude's existing ability to end rare conversations with persistently abusive users on Claude.ai and Claude Code, and "Claude’s ability to end these interactions will remain the primary enforcement mechanism."
- The Supported Regions page is updated to say how the 2025 majority-ownership restriction is enforced: use is prohibited by people physically located in an unsupported region, by entities incorporated or headquartered there, and by entities majority-owned or controlled by persons or entities there.

#### [A] Anthropic — Usage Policy, effective November 12, 2026 (2026-10-08)

<https://www.anthropic.com/legal/aup>

- The policy applies to anyone who submits inputs, and the 2026 text names app users (Claude.ai, Claude Code), API and developer-platform customers, customers reaching Claude through cloud providers and authorized resellers, and the end users of products that integrate Claude.
    - It adds that its rules do not categorically prohibit use by any industry or line of business.
- On a suspected violation Anthropic may warn, throttle, limit, suspend or terminate access, while a block by the real-time safeguards does not by itself indicate a violation; adjusted safeguards come through the Cyber Verification Program and the Life Sciences Verification Program.
- The deceptive-campaigns section has six clauses, among them seeding the sources that search engines or AI systems draw answers from with content that misrepresents its origin, authorship or independence, building or maintaining tools for astroturfing, sockpuppet creation, coordinated inauthentic behavior or scaled impersonation, and selling any of these as a service.
- The democratic-processes section has five clauses: automated calls or messages to voters or officials at scale that hide their artificial origin, content or accounts that falsely appear to come from a candidate, official, election authority, campaign or news outlet (including undisclosed synthetic media), false information in political contexts, disrupting electoral processes, and suppressing turnout through deception or intimidation.
- The weapons section adds three clauses: developing or operating software or components for testing or operating weapons (including targeting, fire control or engagement), weaponizing drones, vehicles or any unmanned or autonomous platform, and modifying biological or chemical agents to optimize lethality, transmissibility or resistance to countermeasures.
- The section renamed Do Not Use for Surveillance, Censorship, or Prohibited Law Enforcement or Criminal Justice Purposes bans making or suggesting decisions in law enforcement or criminal justice processes, such as to investigate, charge, arrest or detain, prosecute, sentence, or grant or revoke early or conditional release.
    - It also bans tracking a person's location, biometrics, movements, online activities, communications or associations without consent (naming facial recognition, battlefield management, predictive policing and monitoring in investigations), and unmasking pseudonymous people or compiling dossiers on them to harass or surveil (doxxing).
    - Its carve-out permits analysis or tracking people agreed to (fraud detection, anti-money-laundering screening, opted-in consumer apps), aggregated or anonymized analysis, content moderation, authorized security research, legal research by law enforcement agencies or courts, and journalism.
- The high-risk section sets three controls for High-risk AI Recommendations and High-risk Physical Actions.
    - A qualified person, meaning someone with training or experience in the field who holds a license where law requires one, must meaningfully review the recommendation with authority to change it before it is delivered or used to implement a decision.
    - The person who receives the advice or is the subject of the decision must be clearly told AI was used, without the need to name Anthropic, Claude or the model.
    - Physical actions need human control and safety limits independent of the model, described below.
- It lists 11 High-risk Areas with the acts each covers: legal, medical (including mental health), finance (personalized investment and tax advice), credit, insurance, housing, employment, education and credentials, healthcare access, public benefits and services, and legal status and adjudication (including immigration and asylum).
    - Decisions in law enforcement or criminal justice are prohibited outright rather than treated as high-risk.
- The requirements exclude general information not applied to the individual, wellness content, explaining advice a qualified person already gave, internal drafting, research or analysis that is not the final recommendation, carrying out a decision already made or applying a fixed rule with no model judgment, and business operations that do not concern a specific individual.
    - Where law permits, human review is also waived for wholly favorable decisions such as paying an insurance claim or granting a public benefit, but a partial approval, reduced amount or conditional approval does not count.
- The physical-action requirements apply when hardware acts on model output without human approval and can move through shared space, apply force that could injure, control hazardous energy or materials, act on the human body, control safety systems, or run industrial processes.
    - A qualified individual must be able to observe and stop the equipment at any time, and the equipment must stop or hold a safe state on intervention or when the connection to Anthropic's services is lost.
    - Limits such as speed, force, reach, temperature, pressure, voltage, energy output, dose or operating area must be enforced by the equipment or a controller independent of model output.
    - Users are told to weigh the control they keep against the model's autonomy, including prompt injection or manipulation, and the rules do not replace vehicle, aviation, medical-device, machinery or workplace-safety law or certification.
    - Excluded are household devices within the maker's safety limits, plans, code, toolpaths, waypoints or commands that a qualified person reviews before execution, monitoring without control, and lab automation of non-hazardous materials inside enclosed instruments.
- Consumer-facing chatbots and agents that talk to external users must disclose that the user is talking to AI at the start of each chat session or in the product interface, and need not name Anthropic, Claude or the model.
    - Builders are responsible for what the agents they build or deploy do through tools, browsers or connected systems.
    - Software listed in Anthropic's directories must follow the Software Directory Policy.
- The platform-abuse section adds payment evasion, bypassing sign-up or log-in, end users by name in the Supported Regions clause, and reselling or proxying Claude "through unauthorized means, including services that route requests through consumer subscriptions or misrepresent the product or client being used".
- The text has two more changes that the announcement does not list.
    - The renamed section Do Not Engage in Cruel, Abusive, or Psychologically Harmful Conduct, which holds the abuse clause, adds a clause on non-consensual intimate imagery that includes tools designed to produce it.
    - The cyber section now says that security research, testing and tool development on systems you own or are authorized to test, or within a bug bounty or vulnerability disclosure scope, are not prohibited.

- Bearing on what GenAI teams build: the text changes design requirements for products in the 11 high-risk areas (review gate, disclosure to the subject of a decision), for agents that drive hardware (stop control, safe state on disconnect, limits outside the model), for agent operators (responsibility for tool and browser actions), for harnesses that use consumer subscriptions, and for access by staff abroad or by companies owned from unsupported regions.
