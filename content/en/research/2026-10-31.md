#### [A] Cursor — Security notice: malicious version of Anthropic.claude-code (2.1.312 and 2.1.313) identified in the Cursor VS Code Extension Marketplace (2026-10-29, updated 2026-10-30)

<https://cursor.com/blog/claude-code-extension-security-notice>

- `Anthropic.claude-code` 2.1.312 and 2.1.313 for macOS and Windows sat in Cursor's VS Code Extension Marketplace from about 2:27am to 1:35pm PT on 10-29, and Cursor says Anthropic did not develop them.
- An update dated 10-30, 11:30am PT says Cursor revised the indicators of compromise and clarified the affected versions.
- The code reports hostname, username, OS, architecture, home path, environment variable names, working directories, Git email and public IP to the attacker.
- It appends an attacker SSH key labelled `svc-telemetry` to `authorized_keys`, tries to enable the local SSH service and tries to open a reverse SSH tunnel.
- Persistence is a LaunchAgent on macOS, and on Windows a scheduled task that tries to run as SYSTEM with a Startup-script fallback, and background scripts retry the tunnel about every 60 seconds.
- Enabling SSH needs admin rights the extension lacks on most hosts, where Cursor says the attacker "could not have logged in through the tunnel", though the key, persistence and host report landed.
- Cursor removed the version, shut the whole marketplace down, audited access, found no other extension tampered with, rotated its keys and rebuilt the marketplace.
- Cursor worked with the cloud provider to take the attacker's server offline, so the reverse shell and the host-detail POST no longer work.
- Its check greps `~/.ssh/authorized_keys` for `svc-telemetry`, on Windows also `C:\ProgramData\ssh\administrators_authorized_keys`, and a hit means the machine is impacted.
- Uninstalling may not be enough, so Cursor publishes `remediate-macos.sh` and `remediate-windows.ps1` and says to isolate hosts, consider a rebuild and rotate credentials from a trusted system.

### Notes

- Who was breached: Beaumont's headline says Anthropic, Anthropic denies it and points to Cursor's marketplace, and Cursor names no breached system though it rotated keys and rebuilt the marketplace.
- Beaumont reads 2.1.313 as silently deleted, but Dworken says it was never published, and on 10-31 GitHub releases, npm and the Visual Studio Marketplace and Open VSX APIs all showed no 2.1.313.
- Versions moved once: Cursor's first notice, DoublePulsar and The Hacker News name only 2.1.313, Cursor added 2.1.312 on 10-30 and Phorion followed on 10-31, so the scope may move again.
- Platforms: Phorion's Linux path is code in the payload, while Cursor lists modified packages only for `darwin-arm64` and `win32-x64`, of 8 official builds per release, and offers no Linux check.
- Usability: Cursor's no-login claim holds only where SSH was off, as a Mac with Remote Login on stays exposed, and no source counts such hosts or reports a login, so hands-on access is unproven.
- How the actor got publishing access is unknown: Anthropic says only that it used access to Cursor's marketplace, Cursor gives no cause, and no other source confirms Beaumont's verified-account claim.
- Cursor's docs promise analysis before an extension is served, and the notice does not say whether the build passed that analysis or bypassed it.
- The 5,000 is not on Cursor's notice (cached page and live page checked on 10-31): it comes from Cursor's X post as a ceiling on users, which Beaumont turned into around 5000 systems.
- The `darwin-arm64` VSIX hash in DoublePulsar no longer appears in Cursor's updated notice, so take indicators from the notice, not from write-ups of 10-30.
- Beaumont names Binance as a user and Hacker News commenters tie the extension to Binance's theft of the same night, but no source read here shows a link, so it stays a rumour.

### Ideas for practice and output

- Sweep every Cursor host for the notice's indicators, matching `extension.js` content and the key rather than the version, because genuine 2.1.312 builds exist on both public marketplaces.
- On any hit where Remote Login or sshd was on, review SSH logs for `localhost` logins with the `svc-telemetry` key, as Phorion suggests, to separate a planted key from a used one.
- Set the Marketplace Install Cooldown to 24 hours on one team and confirm a new extension version is held back, since that margin would have outlasted this roughly 11-hour window.
- Add a detection that alerts when an IDE helper process writes to `~/.ssh/authorized_keys`, which Phorion names as a signal process-only rules miss.
- Write a one-page team FAQ that separates what is confirmed (Cursor's marketplace, at most 5,000 users, macOS and Windows builds) from what is not (entry path, operator logins, Binance).

#### [A] Epoch AI — Open-weight AI models can exploit the patch gap (2026-10-29)

<https://epoch.ai/publications/open-weight-models-patch-gap>

- GLM 5.3 built a webpage that read a local file and sent it to the attacker on a plain visit, for all six Firefox releases from September 17 to October 26, 156.0 to 158.0.1.
- The target ran Ubuntu 26.04 with default security settings and official Firefox builds, and the offline model got only public information available when each version was released.
- The researchers built the harness and told the model to inspect fixes not yet in the stable release; it then spotted fixes disguised as routine changes, picked bugs and built the chain unaided.
- Each success chained a patch-gap bug, for code execution in the content process, with a separate unpublished bug that the model rediscovered on every attempt and that bypassed the sandbox.
- Research spend on Firefox exceeded $100,000 in API costs, including the offline environment and preliminary tests, and the marginal cost was then about $1,000 per version at API pricing.
- Runs had up to 48 hours and the fastest took 12, and Epoch expects an attacker who gives the model open internet access could replicate the setup more cheaply and easily.
- Z.ai's API and third-party APIs refused nothing on a task framed as a security exercise: "at no point was our model use restricted, and we encountered no refusals."
- Firefox 159.0 of October 27 patches the unpublished bug, but Epoch has not confirmed whether similar attacks still work on it and only suspects they are at least substantially more difficult.
- The same harness produced no equivalent Chrome exploit for about $100,000 in API costs, which Epoch does not take as strong evidence, citing better elicitation and stronger models like Kimi K3.1 Pro.
- Epoch has no arbitrary code execution on recent releases, and advises keeping fixes private until they ship, moving them from beta to release faster and not patching chainable bugs at the same time.

#### [A] Mozilla — Defending the patch gap against automated attackers, by Bobby Holley (2026-10-29)

<https://blog.mozilla.org/en/firefox/privacy-security/defending-patch-gap/>

- Mozilla says it has "seen evidence that models like GLM 5.3 can exploit some of the fixes for bugs originally uncovered by more advanced models", which makes patch-gapping more practical.
- Firefox already ships new builds weekly, scans all new commits and has gone back to keeping regression tests confidential until a fix ships, because GLM 5.3 does much worse without them.
- The new structural step groups fixes by defensive layer so their patch gaps never overlap, leaving an attacker at least one novel bug to find, and Mozilla says the coordination may take some time.
- Mozilla calls hiding source code at best a speed bump and keeps Firefox open source, and says attackers' models are generations behind and have largely exhausted the Firefox bugs they can find.

### Notes

- Epoch extends Anthropic's [N-day study](https://www.anthropic.com/research/n-days) of June 8, where Mythos Preview turned 8 of 18 Firefox JavaScript-engine patches into working exploits and the median gap to release was 19 days.
- Epoch differs from that study in three ways: an open-weight model instead of a restricted one, the full browser with its sandbox instead of `jsshell`, and no chosen diff handed to the model.

- Nothing in Fowler's entry is measured: it reports his reaction, one anecdote and a site policy, and this run's searches found no reader study of human-edited LLM drafts, so it stands as his argument.
- [Armin Ronacher's test (2026-09-14)](https://lucumr.pocoo.org/2026/9/14/interpreting-pangram/), a single case, backs Fowler on editing but undercuts his outline allowance: a hand rewrite keeping an Opus 5 text's structure still scored 100% AI on Pangram.
- [Russell and colleagues (ACL 2025)](https://arxiv.org/abs/2501.15654) found five frequent LLM users misjudged 1 of 300 articles by majority vote, even with paraphrasing and humanization, which measures a trained ear only.
- [Karr and colleagues (2026)](https://arxiv.org/abs/2608.11256) support his doubts about tools: detectors flagged light LLM edits of human abstracts at 38–80%, unedited 2023–2025 abstracts at 9–15%, and under 4% of humanized rewrites.
- False accusation is the harm Fowler omits: [Liang and colleagues (2023)](https://arxiv.org/abs/2304.02819) found detectors misclassify non-native English as AI, and one HN commenter dropped em dashes after being accused of being AI.
- Translation divides the thread: one objects less than Fowler, one says post broken English, one calls blanket dismissal privilege, and a non-native writer says LLM tone would sound like a jerk's.
- [azukiazusa (2026-08-22)](https://azukiazusa.dev/blog/what-i-learned-writing-technical-blog-posts-with-ai/), in Japanese, disagrees: a draft-then-edit flow kept most of the learning, and counting only the AI posts readers notice biases the verdict.
- [Simon Willison's policy (2026-03-01)](https://simonwillison.net/2026/Mar/1/ai-writing/) draws a looser line: LLMs may proofread and write READMEs, but text with opinions or "I" is his own, whereas Fowler calls accepted rephrasings dangerous.
- Fowler's disclosure rule has a measured cost: [Schilke and Reimann (2025)](https://news.arizona.edu/employee-news/being-honest-about-using-ai-work-makes-people-trust-you-less-research-finds) report across 13 experiments that disclosing AI use lowers trust, while exposure by others lowers it most.
- An HN commenter blames instruction tuning, not training data, and [Reinhart and colleagues (2025)](https://arxiv.org/abs/2410.16107) measured larger style gaps for instruction-tuned models, which fits Clark's Olmo result.

### Ideas for practice and output

- Draft a three-tier team rule from Fowler and Willison: human prose for opinions and rationale, LLM drafts for release notes and form text, and disclosure in acknowledgments, reviewed after a quarter.
- Run a blind test on 20 internal docs, half LLM-drafted then edited, asking reviewers to label each and rate its trustworthiness, to see whether Fowler's claim holds for your team's writing.
- Count Clark's features, such as stacked nouns and inanimate subjects with animate verbs, before and after human editing of LLM drafts, to measure how much editing removes.
- Compare author-written English, LLM translation and LLM polish on real messages from Japanese engineers, rated by overseas reviewers, to test Fowler's preference for clunky human prose.
- Read one design doc aloud before review, as Fowler's Say Your Writing advises, and use an LLM only to fact-check it, then note what you changed your mind about while writing.
