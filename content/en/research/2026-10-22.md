### Collected information

#### [A] Claude Platform Docs — Migrating to API version 2026-10-21 (2026-10-21)

<https://platform.claude.com/docs/en/api/migration-2026-10-21>

- SDKs send `2026-10-21` from Python 2.0.0, TypeScript 1.0.0, C# 13.0.0, Go 2.0.0, Java 3.0.0, PHP 1.0.0, Ruby 2.0.0 and `ant` CLI 2.0.0; raw HTTP callers opt in with the `anthropic-version` header.
- On `2026-10-21`, Messages, token counting and Batch requests sending `temperature`, `top_p` or `top_k` get 400 even at the default; requests needing other values stay on `2023-06-01`.
- Without them requests sample at the defaults (`temperature` 1.0), as before on Claude 4.7 and later, while on Sonnet 4.6 a lowered temperature is lost: "No other setting replaces it."
- A `document` block directly in an `assistant` message and non-empty `citations` on a `user` text block, including inside `search_result`, now return 400.
- Admin and Enterprise Analytics API responses drop old field names (`roles`, `group_id`, `name`, `group_type`, `actor.email`, `summaries`), and API keys replace `workspace_id` with `scope`.
- The new SDKs' Bedrock and Google Cloud clients send `2026-10-21` too, but Bedrock serves it only for Claude 4.7 and later, so calls to older Bedrock models stay on today's SDK.
- SDKs and `ant` send the key as `Authorization: Bearer` instead of `X-Api-Key`, except the Foundry clients; the API takes either, so only proxies or gateways keyed on `X-Api-Key` are affected.
- Each client holds one credential: two of key, token, credentials, config or profile raise `ValueError` (Python) or `TypeError` (TypeScript), and `ANTHROPIC_API_KEY` wins over `ANTHROPIC_AUTH_TOKEN`.
- `MessageParam` becomes a per-role union, Text Completions leaves the TypeScript, Go, Java and Ruby SDKs and the CLI, and the C# `IChatClient` adapters now ignore temperature, TopK and TopP.
- New majors are Apache 2.0 (earlier versions stay MIT), Go imports move to the `/v2` module path, and the TypeScript platform packages must move to v1 in the same upgrade.

### Collected information

#### [A] DeepSeek on GitHub — DeepSeek V4.1 Flash Inference Deployment Q&A (2026-10-20)

<https://github.com/deepseek-ai/DeepInfer/blob/main/doc/inference_deployment_qa.md>

- DeepSeek says one DeepInfer cluster serves 155 trillion tokens a day for DeepSeek V4.1 Flash, with overall revenue of US$38 per GPU-hour at off-peak ("valley") pricing.
- The system was built to run on several vendors' accelerators, use ordinary 8-GPU machines for prefill and 64–128-GPU supernodes for decode, and keep KV cache for more than 72 hours.
- Prefill runs EP2–8/DP2–8 and decode a wide EP64–128/DP64–128 with no tensor or context parallelism, so the smallest efficient unit is 64 prefill plus 64 decode GPUs, about 1:1.
- Block KV cache lives on a dedicated 3FS cluster of about 100 PiB of SSD, so any prefill machine can hit any prefix and routing needs no prefix affinity.
- The TTL is 3 days for agent traffic and 7 days for chatbot traffic, which would lose 0.5–1% of hit rate at 3 days, and storage runs to about 14.4 TB of logical KV per online GPU.
- DeepSeek has not yet fully open-sourced its KV cache management and load-balancing code, which is coupled to internal infrastructure, and says its balancing reaches about 80% of an ideal benchmark.
- DSpark's confidence-scheduled verification cuts verified draft tokens per step from 5.00 to 3.2–4.4 with the accepted length nearly unchanged, worth +4–7% throughput at about 60 sequences per rank.
- In the decoder layers, SWA bounded replay recomputes only the prompt's last 128 tokens instead of 2,560, which DeepSeek says nearly halves total prefill computation.
- The public FlashMLA lacks one hand-tuned SASS optimisation, leaving its decode kernel 5–10% slower than the internal one, while end-to-end performance is at most 5% apart.
- deepseek-recipe (Rust with Python bindings) maps Chat Completions, Responses and Messages requests to one format and encodes special-token strings in user or tool text as plain text.

#### [A] DeepSeek on GitHub — DeepInfer repository README (2026-10-20)

<https://github.com/deepseek-ai/DeepInfer>

- The Apache 2.0 release offers offline inference with core serving features for DeepSeek-V4.1-Flash only, defaulting to the 1017 checkpoint, and was originally built primarily on vLLM.
- A complete service still needs a KV cache system, vision-encoder/prefill/decode disaggregation (mostly implemented in the engine) and load balancing across data-parallel replicas, none of which ship.

- Batch-invariant inference (`DEEPINFER_BATCH_INVARIANT=1`) and deterministic sampling (adding `DEEPINFER_ENABLE_MTP_VARLEN=0` and a fixed `seq_seed`) are NVIDIA-only.

### Ideas for practice and output

- Prototype a `small-change`-style gate on one repository as a CI check people cannot edit (size cap, no high findings, author history, excluded paths) and measure the share of PRs that qualifies.
- Run `install.sh --dry-run` from `addyosmani/factory` against a throwaway repository, then `bash tests/run.sh`, to see the charter, `gates.sh` and `STOP_IF` at work before borrowing any of it.
- Move a few end-to-end scenarios outside the repository the agent edits, as a holdout set, and count how often agent changes that pass the in-repo tests fail them.
- Audit one coding-agent setup against Agent Baseline's four boundaries: a per-task sandbox, a default-deny egress proxy, no credentials inside the sandbox and approved package sources.
- Track PRs merged per engineer and the share reviewed within 24 hours each month, as Meta and Imprint do, and try freee's review view of facts, reasons and questions on one design review.
