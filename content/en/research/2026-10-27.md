#### [A] Anthropic — Building agents: When to fold subagents into your main agent loop (2026-10-22)

<https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop>

- Diane Sarkis says that in Applied AI's enterprise comparisons "a single agent with skills frequently outperformed" one-prompt and subagent designs on quality, often at lower cost and latency.
- One customer comparing its multi-agent harness with a single agent loop saw a roughly 2x faster runtime, and a company found a dozen specialist subagents made an on-brand experience hard to keep.
- Team-by-team agents bring lossy handoffs, hundreds of overlapping subagents, a Frankenprompt of conflicting rules, local evals and latency, the architecture copying the org chart (Conway's law).
- Subagents stay when context bloat measurably hurts, parallel tasks need disposable fresh contexts, or tool choice fails or instructions conflict, and are split by context rather than problem type.
- It credits models from Opus 4.5 on with handling far more in one loop, notes that thinking cannot be turned off on Opus 5.5 and Fable 5.1, and cites Claude Code's system prompt cut by over 80%.
- The target is one model and context window in an open-ended loop whose harness runs each turn's tool calls in parallel and sets turn and cost budgets and write gates, with the plan kept in context.
- Procedures go into skills, and hard limits and per-user permission checks into tools grouped by user intent, as choice degrades past 30–50 tool definitions, found through tool search.
- Migration starts from an end-to-end eval (10 golden examples to start), merges specialists that chain or co-occur, and folds the rest one by one into skills and MCP tools or calls them as tools.
- In a sample support agent a fold cut latency but broke a passing task in one of two runs, the main agent answering from its order lookup tool without asking the shipping specialist.
- A small central team owns the system prompt and shared eval, team DRIs own skills, and `/claude-api build-eval`, `prompt-audit`, `hillclimb`, `cost-optimize`, `/skill-creator` and `/skill-doctor` help.

#### [A] Anthropic — Using Claude to reduce the attack surface of code (2026-10-20)

<https://www.anthropic.com/research/attack-surface-reduction>

- Chris Rohlf of the Frontier Red Team argues that gating code a deployment need not expose lowers the severity of all unknown bugs in it, exploited ones included, without finding any of them.
- Its three methods seek code reachable by default that no default feature uses, option pairs that silently disable a control, and sensitive code run before authentication or a protocol state change.
- Claude covered 25 projects (10 Public, 11 Gated, 4 Private) of 5M+ lines, in languages including C, C++, Java, PHP and Python, listed 17,000+ options, 3,842 security-relevant, and found 493 issues.
- All 11 Gated projects had needlessly reachable code, including 93 pre-authentication surfaces in their default configurations, though none of these issues was immediately exploitable on its own.
- Of 162 security-sensitive option combinations accepted with no error, warning or documented behaviour, 94 silently turned a security control off and 68 left one inconsistent.
- A hostname-based deny rule failed open in four unrelated projects when reverse DNS lookups were off, and one option pair had silently dropped a client-certificate requirement for 21 years.
- In OpenSSH 10.4, about 4,500 lines of experimental ML-DSA-44 code, some 16% of a default sshd's pre-auth code, were reachable by unauthenticated clients even with the algorithm excluded.
- Claude found two gaps in 10.5's new check, the key blob's inner type and the CA signature path, and the 10.6 fix inside the parser cut about a fifth of default pre-auth code, nearly all ML-DSA.
- Anthropic is integrating the methods, as one reusable Claude skill the post does not release, into OSS-Scanner, and the skill runs three passes, each from an empty context plus a short hand-off.
- Each pass inventories entry points and checks findings by dynamic trace, a default-config gate must keep test and black-box results identical, and one affecting non-default setups goes to a human.

<https://www.openssh.org/releasenotes.html>
