### Collected information

#### [A] OpenAI — Decisions guide (2026-10-06, as fetched on 2026-10-13)

<https://developers.openai.com/api/docs/guides/decisions>

- The API is in public beta with general availability expected in the coming weeks, `gpt-6-luna` is the only model, and requests go to the dedicated `POST /v1/decisions` endpoint.
- A request has three fields: `model`, `input` (a text string, or user messages with `input_text` and `input_image` parts, shared by every question) and `questions`.
    - The response holds an `answers` array that echoes each question's `name`.
- A `predicate` question returns a `probability` from 0 to 1 that a condition is true, and a `choice` question returns one supplied value plus a `probabilities` array and a separate `confidence`.
- A `score` question returns the probability-weighted average of 0-based level indices, so probabilities of 0.1, 0.7 and 0.2 over three severity levels give 1.1, between two levels.
- Independent questions on the same input share one `questions` array and may mix types, while a decision that depends on an earlier answer needs a second request.
- Any question may come back as type `refusal`, and the SDK samples branch on it.
- The guide sends extracted fields, written explanations and tool calls to Structured Outputs on the Responses API or to function calling instead.
- Images must be inline base64 data URLs, and hosted HTTP(S) URLs and `file_id` inputs are not supported by this endpoint.
- It tells developers to set thresholds from labeled examples and the cost of false positives and false negatives, and to add a fallback choice such as `other`.
- Input costs $0.10 per 1M tokens with no charge for cache reads, cache writes or output tokens, while regional processing premiums and long-context multipliers still apply and other `gpt-6-luna` requests keep the normal model pricing.
- It supports Zero Data Retention and HIPAA for eligible customers, and data residency and regional processing in the United States and Europe (EEA plus Switzerland).
- The SDK samples call `client.decisions.create(...)` and need Python 3.26.0, JavaScript 7.30.0, Go 3.73.0, Ruby 0.101.0 or Java 4.78.0, and a Playground is at platform.openai.com/decisions.
- The guide's headline claims typed answers "about 10x faster than the Responses API" and gives no benchmark.

#### [A] OpenAI — API reference: Create a decision (as fetched on 2026-10-13)

<https://developers.openai.com/api/reference/resources/decisions/methods/create>

- A request may carry up to 128 images, as base64 data URLs or publicly accessible HTTP(S) URLs, which contradicts the guide; file IDs, other message roles, function calls, files, audio and item references are rejected, and `detail` takes `low`, `high`, `auto` or `original`.
- A `choice` question takes 2 to 255 unique choices whose values are strings or booleans, and a string and a boolean with the same text are distinct values.
- Answers come back in the order the questions were asked, and a refusal carries only the question's `name` (or `null`) while the other questions are still answered.
- The response `usage` reports `input_tokens`, `cached_tokens`, `cache_write_tokens`, `output_tokens` and `reasoning_tokens`, with 0 output tokens in the example, and an optional `safety_identifier` of up to 128 characters identifies the end user.

#### [A] SQLite — Vec1 Vector Extension (2026-10-01)

<https://sqlite.org/vec1.html>

- vec1 provides approximate nearest-neighbour (ANN) search through SQLite's virtual-table interface, with Euclidean (L2) and cosine distances, in portable C with no external dependencies, using AVX2 on x86 and NEON on ARM.
- Its index is IVFADC (inverted file with asymmetric distance computation) with OPQ (optimized product quantization), and the whole extension is one file, `vec1.c`.
- This page now sits in the main SQLite documentation, was last updated on 2026-10-01 at 11:21:38Z, the minute of the trunk check-in below, and gives the current release as version 0.8, linking `ext/vec1/vec1.c` in the SQLite source tree.
- It builds with `./configure && make vec1.so` (`vec1.dylib` on macOS) at the root of the full SQLite source tree, or `nmake /F Makefile.msc vec1.dll` on Windows, and both produce one binary that picks AVX2 or scalar code for the CPU at run time.
    - Built by hand, e.g. `cc -g -O3 -DNDEBUG -mavx2 -mfma vec1.c -shared -fPIC -o vec1.so`, an AVX2 binary will not run on x86-64 CPUs without AVX2, and the `vec1multi.so` target of `ext/vec1/Makefile` covers several x86-64 levels.
- The roadmap lists possible work without dates: more testing and optimization, a graph-based index as an alternative to IVFADC ("HNSW? DiskANN? Some variant?"), a faster `SELECT count(*)`, SIMD on wasm, int8, int32 or float16 elements besides float32, partition keys, databases from platforms with another float byte order, dot product as a distance and multi-threaded queries.

#### [A] SQLite — Vec1 User Manual and Vec1 Reference Guide (2026-10-01)

<https://sqlite.org/vec1doc.html> / <https://sqlite.org/vec1ref.html>

- `CREATE VIRTUAL TABLE t USING vec1(vector, meta1, ...)` declares one vector column and 0 to 255 untyped metadata columns, and a query uses the table as a table-valued function, `SELECT rowid FROM t(:v, '{K:10}')`, with a hidden `distance` column.
- A vector is a BLOB of 32-bit IEEE floats in machine byte order with finite values only, `vec1_from_json()` and `vec1_to_json()` convert JSON arrays, and the dimension is fixed by the first insert or by the model.
- There are three modes: no index (the default, one row per vector), flat (vectors packed in large BLOBs, over twice as fast for exhaustive search) and ANN, which needs a trained model.
    - The manual advises exact (NN) mode when exact results are required, below about 5,000 vectors, or when training data is unavailable or inconvenient.
- An ANN model is the BLOB returned by the aggregate `vec1_train(vector, '{nbucket:1024, quantizer:"opq", codesize:32, distance:"cos"}')` over a training set, and `INSERT INTO t(cmd, arg) VALUES('rebuild', :model)` installs it and rebuilds the index, at any time and as often as the data needs.
    - Training and rebuilding use several threads through `vec1_config('nthread', N)`, and a model trained on one host works on another with the same float byte order.
- Recommended settings: `nbucket` about the square root of the expected row count (1,000 for 1,000,000 vectors), `quantizer` "opq" for neural-network embeddings, "pq" for engineered descriptors such as SIFT, and "bq" (binary, with a randomized Walsh-Hadamard transform by default) only to minimise training time.
    - `codesize` is 32 bytes for OPQ (48 or 64 if recall is too low) or 1/8 to 1/16 of the dimensions for PQ and BQ, and a training sample of about 100 × `nbucket` vectors usually suffices.
- `nprobe` is the share of buckets a query scans, a fraction below 1.0 or a bucket count from 1.0 up, set per query or per connection with `vec1_config('nprobe', ...)`, with 0.05 as the default.
- ANN distances are computed on the compressed codes and vec1 does not rerank automatically, so the manual has users fetch about 100 candidates and reorder them in SQL with `vec1_l2_distance()` or `vec1_cos_distance()` before `LIMIT 10`.
    - "To be 100% clear, reranking is usually essential for ANN queries with vec1."
- Filtering has two mechanisms: `streaming:1`, which keeps returning rows in roughly ascending distance past K while SQLite asks for more (for metadata in a joined table), and metadata columns, whose `<`, `>`, `=`, `>=`, `<=`, `IS`, `IS NULL` and `IS NOT NULL` constraints run inside the ANN search before the best K are collected.
- A term without a comparison operator, such as `WHERE in_stock AND price < 20000`, is applied after retrieval and silently leaves fewer than K rows, so the manual writes `in_stock = 1`; a visible `LIMIT` can replace K when the query has no join, aggregate or `ORDER BY` and all WHERE terms run inside the search.
- Limits: K from 0 to 33,554,432 (2^25), `nbucket` from 2 to 65,536 (0 disables the inverted file), `codesize` from 0 to 256 bytes (advisory), and `vec1_l2_distance()` returns the squared Euclidean distance while `vec1_cos_distance()` returns 0.0 to 2.0 without needing normalised inputs.

### Notes

- The two documentation sites disagree on the version.
    - `sqlite.org/vec1.html` (10-01) gives 0.8 for code that reported 0.7 until 10-06, while `sqlite.org/vec1` and its benchmark page still give 0.7.

    - No announcement came with the move: the 3.54.0 release notes are silent, and Nuno Cruces asked for one on 10-11.
- "Part of 3.54.0" means the source tree only: the 3.54.0 tag contains `ext/vec1/` at 0.8, but `main.mk` keeps it out of the amalgamation and every distributed package.
    - Applications that use a system, platform or language-bundled SQLite therefore need a separately built `vec1.so` and an SQLite that permits loading extensions; which platforms permit it was not checked.
    - Prebuilt routes found are APSW's PyPI wheels (Python) and ncruces/go-sqlite3 (Go, at 0.7); whether APSW 3.54.0.0 (10-12) bundles 0.8 was not checked.
- Against sqlite-vec, the differences that matter for local RAG:
    - Index: vec1 has a documented ANN path (IVF with PQ, OPQ or binary codes) beside exact flat search, while sqlite-vec's stable releases have none and its rescore, IVF and DiskANN indexes are in alphas with no release since 05-18.
    - Filtering: both apply metadata constraints inside the search (vec1 up to 255 untyped columns without `!=`, sqlite-vec up to 16 typed columns), vec1 adds streaming for joined tables, and only sqlite-vec has partition keys (its docs' example shards by user), which vec1 lists on its roadmap.
    - Element types: vec1 stores float32 only and compresses inside the index, while sqlite-vec also stores int8 and binary vectors.
    - Distances: vec1 has L2 and cosine but no dot product; inference, not a source's claim: with normalised embeddings cosine ranks like dot product, so the gap matters mainly for unnormalised ones.
    - Browser: sqlite-vec runs in WASM today, while vec1 compiles to Wasm, as Nuno Cruces does single-threaded, but has no Wasm SIMD yet, for which his SIMDe route is a stopgap.
- Training is the main operating cost for a growing RAG corpus: an ANN model needs a representative sample (about 100 × `nbucket` vectors) and a retrain and `rebuild` when the data drifts.
    - Dan Kennedy named a training-free online mode as the next focus in July, but the 10-01 roadmap lists only a graph-based index, without saying whether it would avoid training.
    - The 0.7 post's RaBitQ quantizer does not appear under that name in the docs, which list only "bq", binary quantization with a randomized Walsh-Hadamard transform, so whether "bq" is that quantizer is unconfirmed.
- Recall depends on reranking: on agnews the 10 best by compressed distance hold only about 62% of the true top 10, so a retriever must fetch about 100 candidates and reorder them in SQL, which the manual leaves to the user.
- Footprint is undocumented: no source gives disk or memory per vector; inference, not a source's claim: reranking reads the stored `vector` column, so the table appears to keep full vectors beside the codes.
- Robustness: the August record backs the old caveat that testing is insufficient, and fixes for corrupt metadata arrays and rounding errors continued in October.
    - Who filed the August reports is not visible without logging in to the vec1 forum, so tying them to Lee Butterman's agent-found bugs rests on timing only.
    - Lee Butterman's count of over half a dozen SQL-reachable memory-safety bugs is his claim; no source confirms the number.
    - `SQLITE_DIRECTONLY`, per SQLite's [function flags](https://sqlite.org/c3ref/c_deterministic.html), lets a function run only from top-level SQL and not from views, triggers or schema, guarding against database files whose schema was altered to call it.
- mattn dates the start of development to about January from the file header, which reads 2026-02-04; Dan Kennedy's first forum post on vec1 is from 2026-02-26.
- For scale, the agnews run serves about 1,300 to 2,250 reranked queries per second on one desktop CPU thread at 0.93 to 0.96 recall over 770,000 1024-dimensional vectors, well beyond the 100,000 vectors at which the March forum user says a sqlite-vec fork stopped working for him.

#### [A] AWS Open Source Blog — Introducing Strands Box: AI agent sandboxes powered by Dogwood, by Fernando Dingler (2026-10-07)

<https://aws.amazon.com/blogs/opensource/introducing-strands-box-ai-agent-sandboxes-powered-by-dogwood/>

- Strands Box enters developer preview as an Apache 2.0 sandbox that pairs OS-level containment (Seatbelt on macOS) with Dogwood policies, aimed at coding assistants and other agents that run without human review of each action.
- It embeds the Dogwood Local Engine, which judges each requested action against the policy and the agent's recorded history, and enforces the allow or deny outside the agent.
- Containment fixes what the agent can reach on the host and the network, and policy decides actions inside that boundary at four enforcement points: an egress gateway that proxies all outbound traffic, Strands Shell, Pydantic's Monty for Python, and an MCP broker.
    - The two interpreters and the broker run in Box's own process outside the sandbox, where the agent reaches them as ordinary `bash`, `python3` and MCP commands over a local socket, a trade-off AWS says widens the trusted computing base.
- All enforcement points share one event history and one vocabulary, so a read through either interpreter is `fs:read` and a request from `curl` or Python is `http:request`, which lets one rule block outbound HTTP after a read of customer data whichever tool did it.
    - Strands Shell expands `rm -rf build/` into one `fs:delete` decision per file, so a `forbid` on `fs:delete` stops it before anything is removed while ordinary edits pass.
- Paths granted directly in `box.toml`, such as a project directory that a harness's built-in file tool opens, are bounded by containment alone and never enter the policy history; AWS wants policy to cover more and says it is eager to adopt the Endpoint Security additions in macOS 27.
- AWS passes over a container or microVM for local use because it adds a guest environment to provision and wire to local files and tools, and over harness permission prompts because they run inside the agent's process and judge the tool call, not the files and hosts it touches.
    - The same `box.toml` and `policy.dw` apply whichever harness runs in the box.
- The gateway attaches a credential only to a request the policy permits, swapping the agent's placeholder for the secret, with Bearer token, custom header, HTTP Basic, query parameter and AWS SigV4 supported.
    - `secret.inject = "always"` injects a token without any placeholder, and a credential binding opens no destination by itself.
- Rules use Cedar syntax with the agent as the fixed principal, so they match on actions such as `Box::Action::"shell:spawn"` or `Box::Action::"http:request"` and read the host, port, method, path or program path from `context.input`.
    - AWS also released the `authoring-box-policy` agent skill, expecting most users to have an LLM write their policies.
- The temporal example caps Slack `POST /api/chat.postMessage` at three per 10 minutes with `formerly within 10m` and `count for (t: Timepoint)` over `::response` events with `output.status: 200`, so refusals do not count, whereas binding `::request` would count attempts.
    - A refused post gets HTTP 403 with `policy denied this operation`, the rule's `@id` and its `@description`, so the agent can wait instead of retrying.
- Next steps: other operating systems, a CLI that detects installed harnesses and generates `box.toml` with a baseline policy, packaging agents built with the Strands Harness SDK, LangChain or the Claude Agent SDK together with Box for Amazon Bedrock AgentCore, ECS or Kubernetes, and liveness rules in Dogwood.

#### [A] strands-agents/box — README, security model, policy guide, limitations and the v0.1.0 release (2026-10-07)

<https://github.com/strands-agents/box> / <https://github.com/strands-agents/box/blob/v0.1.0/docs/user/security.md> / <https://github.com/strands-agents/box/blob/v0.1.0/docs/design/limitations.md>

- The getting-started path needs an Apple-silicon Mac on macOS 15 or later, Node.js 22.21 or later from Homebrew, and Claude Opus 5 on Amazon Bedrock in `us-west-2`.
- security.md splits two tiers: `box.toml` sets what the workload's own processes can open, enforced by the OS from before the first process with no policy decision and nothing in the decision log, and `policy.dw` decides each request sent through the box's trusted process.
    - For a `[tool.<name>]` program, or a host program admitted by a `shell:spawn` permit, policy decides only whether it runs, and none of its file operations or child processes.
- Box always refuses requests into the box directory and reads or changes of the loaded `box.toml` and `policy.dw`, but cloud metadata protection is only two `forbid` rules, `metadata_hosts` and `metadata_addresses`, that each policy must carry because the gateway has no built-in block.
    - The repository's example policies carry both, while the getting-started policy omits them and security.md asks operators to add them.
- Documented limitations include that a `fs:read` permit without a path condition reaches `~/.aws` and `~/.ssh`, that overlapping permits load without a warning, and that a `::response` budget can be overspent by requests in flight while a `::request` budget is exact but spent by refused attempts.
    - A rule that calls a temporal macro such as `count_within` loses its count when any text before the call changes, even a comment, whereas an inline `when temporal` clause keeps it.
    - The decision log records the rule and the path but not the operation, so a `cat` and an `ls` of one file look the same.
- A denial reads `policy denied this operation on '<path>' [policy: <id>]: <description>` and reaches each caller differently: exit status 126 for a refused shell command, `PermissionError` in Python, HTTP 403 for a request, and JSON-RPC error `-32001` for an MCP call.
- The vocabulary has ten actions, `fs:read`, `fs:write`, `fs:delete`, `fs:move`, a reserved `fs:other`, `net:connect`, `http:request`, `shell:exec`, `shell:spawn` and `mcp:call`, plus one generated per discovered MCP tool, and each outbound call needs both a `net:connect` and an `http:request` permit.
    - Filesystem responses carry an `output.result` of `completed`, `descriptor_issued` or `indeterminate`, and the policy crate README says `descriptor_issued` is kept distinct on purpose because the bytes move after the admitted call, so a rule counting completed writes excludes it.
- Decisions go to `<box_dir>/private/telemetry/records.jsonl` as OTLP JSON that is neither signed nor chained, and a record is lost without notice when a target fails.
- limitations.md says Box provides no resource limits, no isolation between tenants, no protection from kernel exploits, no containment of remote MCP servers or of defects in its own trusted process, and no tamper-proof audit trail.
- The policy guide's write-budget example, at most 20 `completed` content writes per hour, shows a `tee` write refused under `write_budget`, and the text is unchanged on `main` as of 10-13.

#### [A] shimitaro (Zenn) — Autopilot assumes a human who can disengage it: what aviation teaches about keeping engineering skills in the AI era (2026-10-05, in Japanese)

<https://zenn.dev/shimitaro/articles/eb45d8d63c7bd1>

- Published at 17:06 JST on 2026-10-05 as an "idea" article with the Zenn topics AI, AWS and SRE, according to the [Zenn API](https://zenn.dev/api/articles/eb45d8d63c7bd1); it is the author's only Zenn article.
    - At 10:23 JST on 2026-10-13 it had 80 likes, 20 bookmarks and no comments, and the author's article list showed 82 likes at 10:47 JST.
    - It closes by announcing a follow-up on putting the drills into a team's routine, which had not been published by then.
- The trigger: in a flow where one agent implements, another reviews and writes tests, and the author skims the diff and merges, he stalled before approving a CDK diff that sat unread under an AI review saying there was no problem.
- He accepts rising abstraction (assembly to C, to Java or Python, to frameworks) and names the one difference: a compiler is deterministic and framework bugs are shared, while an agent's output changes on every run and is plausibly, confidently wrong, a lower layer that sometimes fails silently.
- His thesis is that aviation regulators maintain the ability to take over from automation rather than to fly without it, so engineers should keep the ability to take over from AI rather than to write without it.
- He builds the case on FAA SAFO 13002 (2013-01-04), the FAA final rule 78 FR 67800 (2013-11-12), the PARC/CAST report on flight path management systems (2013), CAST SE-30 (2008), SAFO 17007 (2017-05-04), FAA AC 120-123 (2022-11-21), EASA SIB 2013-05R1, and evidence-based training (EBT) in ICAO Doc 9995, EASA NPA 2018-07 and Opinion 08/2019.
- A Mermaid diagram maps aviation's loop (use the autopilot, monitor it, recognise an anomaly, disengage, take over, recover) onto AI development (let the AI implement, monitor its output, recognise a wrong implementation or judgement, switch from AI to human, read the code to find the cause, fix and recover).
    - A table pairs the autopilot with the coding agent, the flight plan with requirements and design, mode awareness with understanding what the AI is doing, the simulator (FSTD) with drills in failure analysis and review, and EBT with the path from incident to postmortem to drill material.
- Proposed drills: find dangerous settings planted in Terraform or CDK, list IAM over-permissions such as `"Action": "*"` or an unneeded `"Resource": "*"`, root-cause an ALB returning 502 from the access logs and target settings, find problems in code the AI judged fine, stop an IaC change that leads to deleting a database, imagine failures that slip past AI-written tests, and verify a wrong fix the AI proposed.
- Worked example: in a stack definition shared by production and staging, an AI-approved two-line diff on an `rds.DatabaseInstance` changes `removalPolicy` from `cdk.RemovalPolicy.RETAIN` to `DESTROY` and `deletionProtection` from `true` to `false`.
    - The expected answer blocks it for production: `removalPolicy` sets both CloudFormation's `DeletionPolicy` and `UpdateReplacePolicy`, so a stack deletion or any replacement (the new instance is created before the old one is deleted) would delete the production database, with no deletion protection left to stop it.
- For daily work he rejects uniform rules such as reading a set number of lines a day, mirroring SAFO 17007's advice against quotas, in favour of deliberately reading by hand only the high-risk diffs (IAM policy changes, IaC that can delete data, network configuration), even after the AI review has passed them.
- From EBT he takes a loop: anonymise the code or configuration behind a production incident, rebuild it in a small reproduction environment and drill it regularly as a team, with no pass or fail, because grading makes exercises easier and reports more guarded.
    - AI-era material, such as wrong fixes the AI proposed, diffs its review missed and failures its tests let through, becomes training for automation surprise.
- Limits he concedes: most software failures can be rolled back and no regulation mandates training, one engineer may watch several agents and repositories, and manual flying leans on motor skill while root-causing code is cognitive.
    - He argues that AI errors in software are almost all silent, without the alarms a cockpit gives, so recognising the anomaly is the hardest step and drills should centre on finding problems in what the AI calls fine.
- With the agent as pilot flying (PF), the human becomes pilot monitoring (PM), but an aviation PM is trained to fly as PF, so implementation skill cannot drop to zero.

#### [A] FAA — SAFO 17007, Manual Flight Operations Proficiency (2017-05-04, background)

<https://www.faa.gov/sites/faa.gov/files/other_visit/aviation_industry/airline_operators/airline_safety/SAFO17007.pdf>

- It asks air carriers for training and line-operations policies that develop and maintain manual flight proficiency, based on recommendations of the Flight Path Management Workgroup of the Air Carrier Training Aviation Rulemaking Committee.
- Curricula should follow the philosophy that "manual flight is the foundation upon which other technical flying skills are built", while recognising that manual flight involves more than motor skills.

#### [A] FAA — SAFO 13002, Manual Flight Operations (2013-01-04, background)

<https://www.faa.gov/sites/faa.gov/files/other_visit/aviation_industry/airline_operators/airline_safety/SAFO13002.pdf>

#### [A] Casner, Geven, Recker and Schooler (Human Factors) — The Retention of Manual Flying Skills in the Automated Cockpit (December 2014, background)

<https://gwern.net/doc/technology/2014-casner.pdf>

- The NASA Ames-led study that SAFO 17007 lists as related guidance (DOI 10.1177/0018720814535628) had 16 airline pilots fly routine and non-routine scenarios in a Boeing 747-400 simulator at varied levels of automation.
- Instrument scanning and manual control were mostly intact even when rarely practised, but the cognitive tasks of manual flight, such as tracking position without the map display, deciding the next navigation steps and recognising instrument failures, showed more frequent and significant problems.
    - With a faulty altimeter, 75% of pilots followed it until they were more than 300 feet off the assigned altitude, and only 69% and 63% cross-checked the other altimeters and heading indicators.
- Pilots spent 20.0% of the time in task-unrelated thought under autoflight, against 11.7% under manual control and 6.9% with raw data and manual control, and those whose thoughts drifted more made more navigation errors (r = .56, about 30% of the variability).
    - The authors conclude that retaining the cognitive skills "may depend on the degree to which pilots remain actively engaged in supervising the automation".

#### [A] Claude Platform Docs — Multiagent orchestration (as fetched on 2026-10-13)

<https://platform.claude.com/docs/en/managed-agents/multiagent-orchestration>

- The `multiagent_20261001` type combines three settings: `subagents` and `workflows`, both enabled by default, and `advisor`, disabled by default.
- With subagents the agent delegates turn by turn and can send follow-ups to persistent threads, one level deep and at most 25 child threads at a time; with workflows, "Claude writes a program to orchestrate agents without Claude's direct involvement", while the primary thread stays free to talk to the user and check on runs.
- The docs recommend workflows for most work that needs more than one agent: work with many pieces, parallel work, or a long task that should finish sooner, such as audits, migrations, deep research and cross-checking.
- No API call starts a run: the agent decides from the `user.message` whether and when to start one, and the message or the system prompt is the only way to steer that.
    - Permission policies apply to the tools that a run's agents call, not to starting the run.
- A run's agents are inline agents that the workflow defines, with a system prompt it writes and the model of the session's agent, or predefined agents listed in `workflows.predefined_agents` (up to 20, a list separate from `subagents.predefined_agents`).
    - Running some of a run's agents on another model requires creating them as agents and listing them there.
- Listed agents are pinned to the version resolved at create or update, cannot themselves have `multiagent` set, and must all pin the same `inference_geo` as the lead agent or none may pin one; `{"type": "self"}` lists copies of the agent itself.
- An inline agent gets the session agent's MCP servers and tools, and vault credentials apply to every thread, so restricting a run's access means setting `inline_agents` to `{"type": "disabled"}` under `workflows` and listing narrower agents.
- All agents share the session's sandbox, files and vault credentials, while each works in its own context-isolated session thread.
- The sample system prompt tells a contract reviewer to start a run when asked to review more than a few contracts and to review one or two itself, and suggested additions cover splitting (one agent per contract, then a second agent reviewing every contract), failure (list unreadable contracts as not covered) and a one-hour time limit.
- The `ant__` tool-name prefix is now reserved: an agent with a custom tool named `ant__…` fails every update and every new session with a 400 error until the tool is renamed in the same update that turns workflows on.
- Moving an agent from the older `coordinator` type (subagents and advisor only) replaces the whole `multiagent` block, so leaving out `workflows` and `subagents.inline_agents` enables both, and leaving out the subagent list empties it.
- A session copies the setting at creation, `{"type": "disabled"}` turns workflows off, and sending `null` turns them back on because the default is enabled.

#### [A] Claude Platform Docs — Workflow runs (as fetched on 2026-10-13)

<https://platform.claude.com/docs/en/managed-agents/workflow-runs>

- A run has three layers: the run, optional named phases, and agent threads in which the program fans out agents, passes one agent's result to another, repeats a step until a review passes or rounds run out, and handles or propagates a failed agent.
    - Results go to the program, not to the session's agent, which gets a turn to read what the run did when it ends.
- Limits: 64 threads working at once in one run, a number the API does not guarantee; 1,000 agents started over a run's life, after which the run ends with `thread_limit_error`; a 24-hour lifetime by default that the agent can shorten; and 10 open runs per session by default, idle ones included.
    - Retries of a failed agent on new threads can take a run past 1,000 threads, the server has further limits that are not listed, and a session can start any number of runs over its life.
- Events on the session stream: `workflow_run.created` (with a `wrun_…` ID, a name, a description and the declared `phases`, all text the model wrote), `workflow_run.status_running`, `workflow_run.status_idle`, `workflow_run.phase_started` and `workflow_run.phase_ended`, `workflow_run.status_ended` with a `result`, and `workflow_run.error`.
    - Run events do not trigger webhooks, and no endpoint lists runs, so a client rebuilds run state after reconnecting by listing past events with a `types` filter.
- A `completed` result only means the workflow finished: a run can end `completed` although work on its threads failed or a thread could not be created, and the error results are `timeout_error`, `program_error`, `thread_limit_error` and `unknown_error`.
- Runs do not nest: only the agent on the primary thread starts one, a run's threads are exempt from the 25-child-thread limit, the agent cannot send them follow-ups, and the server archives each by the end of its run.
- You do not see the workflow's code, the tool calls that start and manage runs, or what each thread returns to the program; a tip says to ask the agent, once the run has ended and the session is idle, to print the workflow word for word without starting another run.
- No client event ends a run: `user.interrupt` stops the agent's turn while runs may pause or keep going, so stopping means a `user.message` asking the agent to stop them, and archiving or deleting a session, or updating its `agent`, can return 400 with `workflow_run_open` while a run is open.
- The session stays `running` while a run runs, even when none of its threads is working, and the work is done only once every run seen has its `workflow_run.status_ended` and a later `session.status_idle` arrives with `end_turn`.
- "A run has no price of its own": its agents' tokens are billed at each model's rates and count toward the session budget, and one run's usage is the sum of `usage` over the threads that carry its `workflow_run_id`.
- At the budget every open run pauses and can pass it by one request per working thread, while a paused run's lifetime keeps running down, so a run left paused can end with `timeout_error`.
- A run's model requests count toward the organization's Messages API rate limits along with its other traffic, and because a run can create more than one thread for the same piece of work, the docs ask for tools that are safe to call twice.
- The worked example asks which of 300 contracts have a change-of-control clause and shows a run with the phases "Read the contracts" and "Reconcile the findings" ending with the answer that 41 have one (an illustration, not a measurement).

#### [A] Claude Platform Docs — Session budgets and the Claude Managed Agents section of Pricing (as fetched on 2026-10-13)
